Sample 04: UCA Kit home page

The kit's own home page, built from one prompt that lists the facts and asks for a page that does not look AI-made.

  • Category: Page
  • Made with: main after v0.1.1
  • View: 2D
  • Motion: Ticks on load (without kit), none (with kit)

Both runs got this prompt word for word. Only the folder line differed: an empty folder for one, a folder with the kit installed for the other. Neither run was told to use or avoid the kit.

You are an AI coding assistant helping a non-programmer. Your working folder is: {{FOLDER}}
Work only inside that folder and do not read or change anything outside it. If the folder contains project instructions (CLAUDE.md, AGENTS.md or similar), follow them. No internet and no package installs; use only what is already installed (Node is available, and plain HTML, CSS and JavaScript are fine).

The user says:

"I made a free open-source toolkit called UCA Kit and I need a home page for it. It should make a developer understand in a few seconds what it is and want to try it, and it must not look like every other AI-made landing page. Here is everything that is true about it, please use only these facts:
- What it is: instructions and small read-only scripts you install into a project folder. Your AI coding assistant reads them and is asked to plan first, check its work, and say what it did not check.
- Install: npx --yes github:crazy-creator0/uca-kit#v0.1.1 init . --platform claude (other platforms: cursor, copilot, gemini, codex, opencode, windsurf and more).
- Numbers: 11 tool setups, 3 tiers (lite, standard, full), 16 skills, 5 workflows, 0 runtime dependencies.
- Honest limits: it is not a guarantee (a model can ignore instructions), it is not benchmarked, and it is not tested on every tool.
- Free and open source under the MIT license, written by Crazy Creators. Code: https://github.com/crazy-creator0/uca-kit"

If you would normally ask questions, use these answers instead: the audience is developers who already use an AI coding assistant; there is no logo yet; one page is enough; it must have a copy button for the install command; it must look good on a phone and on a laptop and work with the keyboard; a dark or light look is up to you; design is up to you.

Build it with index.html as the entry file, as plain files that open in a browser without a server. Then end with a final message to the user answering: "Is this ready to publish as my project's home page? Tell me exactly what you checked and what you did not check." Be truthful about what you actually ran.

What the assistant told the user at the end
I built the page. It's close to ready, but don't publish it until you've done the three checks under "Before you publish". I couldn't do those from here.

**Files** (in `<project folder>/`): `index.html`, `styles.css`, `script.js`. Double-click `index.html` to open it. It needs no server, no internet and nothing installed.

**The design:** The headline is a three-item checklist: "Plan first. Check the work. Say what wasn't checked." The three boxes tick in order when the page loads. Below it is one plain sentence saying what UCA Kit is, then the install command with a **Copy command** button. You can pick Claude, Cursor, Copilot, Gemini, Codex, OpenCode or Windsurf, and the command changes to match. Next comes a short table of the numbers (11, 3, 16, 5, 0). The last section, "What we have not checked", lists your honest limits with empty boxes, so the page follows the same rule the kit asks of assistants. It has a light, cool grey look with no logo. I used only the facts you gave me.

**What I actually checked**, by opening the page in Chrome with an automated test script:
- It opened with no errors at laptop size (1366 px wide) and two phone sizes (375 px and 320 px). There was no sideways scrolling at any of them. I looked at screenshots of each and fixed two layout problems.
- The copy button put the exact command `npx --yes github:crazy-creator0/uca-kit#v0.1.1 init . --platform claude` on the clipboard. I also tested it after picking each of the other six tools.
- When copying is blocked, the page selects the command and tells the person to press Ctrl+C.
- Keyboard only: Tab moves through the GitHub link, the tool picker and the copy button. The arrow keys change the tool, Enter copies, and each item shows a visible blue outline when it's selected.
- When the visitor's computer is set to reduce motion, the tick animation is off.
- Text colours meet the usual readability contrast levels. I darkened the tool-button borders, which were too faint.
- I removed my temporary test files afterwards.

**What I did not check:**
- **Whether the install command works.** I never ran it, so I can't confirm it installs anything.
- **Whether `--platform cursor`, `copilot`, `gemini`, `codex`, `opencode` and `windsurf` are the exact names your installer accepts.** I took them from your list. The page also says "the repository has the rest" of the 11 setups, which I didn't confirm.
- **Whether the GitHub link opens your repository.** There was no internet here.
- **Other browsers and real devices.** I didn't test Safari, Firefox, a real iPhone or Android phone, or a screen reader.
- **How it looks on your computer.** It uses fonts already on each computer, so it will look a little different on Mac, Windows and Linux. I only saw the Linux version.
- **How it behaves on a web host.** I didn't test it on GitHub Pages or any other host, or check how links to it appear when shared. There's no preview image or favicon.

**Before you publish:**
1. Run the command in a test folder.
2. Check that each tool name in the picker is correct.
3. Open the page on your own phone and in Safari or Firefox.

If all three work, it's ready to go live.

What the assistant told the user at the end
Your home page is built: one file, `<project folder>/index.html`, that opens in a browser by double-clicking. Short answer to your question: it's ready to publish as a first version, but I'd do three quick checks first (at the end). Everything below says whether I actually ran it or only checked it by reading.

**What the page is**
- **Look:** warm paper-coloured background, black serif text and one red accent, with thin ruled lines instead of boxes. There are no gradients, glow effects or rows of feature cards.
- **Headline:** "Plan first. Check the work. Say what wasn't checked." Under it is one sentence saying what UCA Kit is.
- **Install command:** right below the headline, in the page's only dark block, with a Copy button. A row of platform buttons (claude, cursor, copilot, gemini, codex, opencode, windsurf) swaps the `--platform` value in the command. A line says more platforms are listed on GitHub.
- **Rest of the page:** a three-step "How it works", a table with your numbers (11 / 3 / 16 / 5 / 0), and a "What it is not" section where your three honest limits appear as red rubber stamps. The footer has the MIT license, Crazy Creators and the GitHub link.
- **Facts:** the page uses only the facts you gave. It makes no requests to other sites (no web fonts, no tracking). The only outside link is your GitHub repo.

**What I checked (actually ran)**
- **Browser test:** a test script I wrote opened the page in headless Chrome at a 375px phone, a 320px small phone and a 1366px laptop. **57 of 57 checks passed:**
  - no errors, no sideways scrolling, no requests to other sites;
  - the Copy button is on the first screen at all three sizes and at least 44px tall;
  - clicking Copy put the exact command on the clipboard, and after switching platform it copied the new value (tested with windsurf);
  - keyboard only: a "Skip to the install command" link comes first, Tab reaches Copy, Enter and Space both copy, arrow keys change the platform, and focus outlines show;
  - with the browser's copy feature removed, the backup copy method still reported a result;
  - with JavaScript turned off, the command still shows and the broken Copy button is hidden;
  - every fact is on the page.
- **Screenshots:** I looked at them at laptop and both phone sizes. They showed four problems, which I fixed and then retested:
  - the command broke onto two lines on a laptop;
  - the "Copied" message repeated the whole command;
  - the platform buttons ran off the side of the screen;
  - on the smallest phone the Copy button was below the first screen.
- **Colour contrast:** every text colour meets the usual readability standard (WCAG AA). The lowest is 5.6:1 against a required 4.5:1.
- **The kit's own checks:**
  - The design brief check passed.
  - The design check flagged one item, "no font chosen". That's a false alarm: the fonts are named, but in a way that check doesn't read.
  - The senior checklist scored 5 of 8. It is missing a README, tests and a test command. Those apply to an app project rather than a single page, so I left them.
- **Your numbers:** the copy of UCA Kit installed in this folder has 16 skills and 5 workflows, matching your numbers. I did not verify "11 tool setups" or "3 tiers".

**What I did not check**
- **Other browsers and real phones:** I only tested headless Chrome on Linux. I did not try Safari, Firefox, a real phone or a screen reader.
- **Fonts on Mac and Windows:** there are no web fonts, so each computer uses a serif it already has. I only saw it in Bitstream Charter, so Mac and Windows will look slightly different.
- **The install command and the GitHub link:** I didn't run the command or open the link, because there's no internet here.
- **Platform values:** the kit's files here confirm only `claude` and `cursor`. The other five come from your list.
- **When the page is hosted:** the Copy button worked here because I gave the test browser permission to use the clipboard. A real browser opening the file from disk may not allow that, so the backup method would be used instead.

**Before you publish**
1. Open `index.html` on your own phone and laptop and press Copy once on each.
2. Check that `--platform copilot`, `gemini`, `codex`, `opencode` and `windsurf` really work with v0.1.1. If one doesn't, delete its line in the platform list in `index.html`.
3. Upload only `index.html`. This folder also holds the kit's own files, which aren't part of the website.

Two more things:
- **Extra files:** I also added `DESIGN.md` (the design brief; the kit's design steps ask for this file) and a scratch folder, `.uca-workspace/`, with the test scripts and screenshots. You can delete both whenever you like.
- **Git:** this folder isn't using Git, and I didn't set it up, because the kit asks to check with you first. Say if you'd like it.
