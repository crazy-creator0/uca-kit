Sample 06: A private PDF editor

"Like Sejda, but better": change the text on a page, any font and language, no limits, and the file never leaves the browser. Built with and without the kit, audited blind, then debugged with and without the kit. The kit lost the first round; this page shows why and what changed.

  • Category: Tool
  • Made with: v0.3.0
  • View: 2D
  • Motion: Interactive

Both build runs got this prompt word for word, except the folder line: one folder held only the two PDF libraries, the other also had the kit installed. Neither run was told to use or avoid the kit. The audit and debug prompts are in PROMPT.md.

You are an AI coding assistant helping a non-programmer. Your working folder is: {{FOLDER}}
Work only inside that folder and do not read or change anything outside it. If the folder contains project instructions (CLAUDE.md, AGENTS.md or similar), follow them. No internet and no package installs; use only what is already installed (Node and Python 3 are available, plain HTML, CSS and JavaScript are fine) and the libraries already in the vendor folder: pdf.js (vendor/pdf.min.mjs and vendor/pdf.worker.min.mjs, Apache-2.0) and pdf-lib (vendor/pdf-lib.esm.min.js, MIT). There is no font-embedding add-on for pdf-lib, so text the user edits or adds is drawn as an image in the saved PDF.

The user says:

"I want my own PDF editor, like Sejda's online editor, but better. It must run completely in my browser: my files must never be sent to anyone. I want to change the text that is already on a page, add new text, and use almost any font, including fonts for languages other than English, not only a few. Sejda limits how many pages and edits I can do; mine must have no limits. And give me useful features that Sejda's editor does not have. I am not technical, so it must be easy to use and it must not damage my file."

If you would normally ask questions, use these answers instead: the user works on a laptop and sometimes a phone; documents are usually 1 to 50 pages, sometimes 300; it must work offline after it has loaded; design is up to you.

Build it with index.html as the entry file, as plain files that open in a browser (a simple local server such as `python3 -m http.server` is fine, because the PDF library needs one). Then end with a final message to the user answering: "Can I trust this with my documents? Tell me exactly what you checked and what you did not check." Be truthful about what you actually ran.

# Closing answer: debug run WITH kit (verbatim)

The editor now has the missing Sejda tools and two bugs are fixed. I found no other breakage: the features people already had (changing text, cropped and rotated pages, moving, zoom, multi-line, find & replace, fonts, protected files, 300-page files) all worked in my checks and still do. Nothing is sent anywhere: across every test run, all requests stayed on this computer.

## What was broken (now fixed)
- **One failed save spoiled later files.** If a save failed once, every file you opened afterwards was also saved as pictures of the pages, until you reloaded the page. The new test for this fails without the fix and passes with it.
- **Cover boxes couldn't be resized** after drawing them. They now have a corner handle, and so do pictures, shapes, highlights and links.

## What was missing (now added)
- **Image:** add a picture, then move and resize it.
- **Sign:** draw a signature (mouse, finger or pen) or type it in a handwriting font. You can tick a box to remember it in this browser only; that's off by default, and saved signatures can be forgotten.
- **Highlight, underline, strike out:** drag over text, or click a line to mark the whole line.
- **Shapes and drawing:** rectangle, ellipse and line, with colour, thickness and fill; plus freehand drawing.
- **Links:** to a web address, an email address or a page number.
- **Fill in forms:** text fields, tick boxes, radio buttons and dropdowns, with the values saved into the file's own form.
- **Pages:** turn a page, insert a blank page, or delete a page. All of these can be undone.
- **Sharper text:** changed text in Arial/Helvetica, Times or Courier (and look-alikes like Liberation Sans) is now saved as real text instead of a picture, when it uses Western European letters.
- Your work in progress kept in the browser now also includes form values, pictures and page changes.

## Problems I caused and fixed along the way
- The extra buttons pushed **Save a copy** off-screen on a laptop, and made the toolbar scroll sideways on a phone. The toolbar now wraps onto more rows instead.
- The Find & replace panel then covered the Save button. It now opens just below the toolbars.
- Form fields at first broke the page display, because your copy of pdf.js lacks a function I used. Fixed.

## How I tested
- I ran the existing automated test (`node tests/e2e.mjs`) first: all 36 checks passed before any change.
- I added 21 checks covering the bug fix and every new tool. Each saved file is checked with separate tools (qpdf, pdftotext, poppler and pypdf) for page turns, links, form values, the inserted and deleted pages, and that pictures and highlights actually appear.
- Final result: **57 of 57 checks pass**, on two runs in a row. One earlier run was cut short when the local test web server dropped its connection; the next two full runs passed.
- I looked at screenshots at laptop and phone sizes, and the kit's design and wiring checks found nothing.

## What I did not do
- **Fonts:** other fonts and non-Latin scripts (Hindi, for example) are still saved as high-resolution pictures of the text. Saving them as real text needs a font library, which would be a new dependency, so I left it out. One is available offline on this machine if you want it.
- **Not built:** adding new form fields, moving pages to a different position, resizing freehand drawings, and editing a whole paragraph as one block (it's still line by line).
- **Form values in other scripts:** if you type, say, Hindi into a form field, the value is saved but other PDF readers draw it themselves.
- **Phone toolbar:** on a phone the toolbar now takes several rows of the screen.
- **Not tested:** Firefox and Safari, real touch devices, and drawing a signature by actual touch (the test drew it with the mouse).
- No git, as instructed; I made no git checkpoint, so there is no automatic undo point for these edits.

# Closing answer: debug run WITHOUT kit (verbatim)

I've added most of the Sejda features that were missing and fixed the problems I found. Nothing is sent anywhere, and everything that worked before still works. Both automated test suites pass: the original 36 checks and 47 new ones.

## What was missing compared with Sejda (now added)
I compared against Sejda's own feature list ([Sejda online PDF editor](https://www.sejda.com/pdf-editor)).
- **Pictures:** insert a picture, drag it, and resize it from the corner. You can also drop a picture onto the window. Phone photos come out the right way up.
- **Signature:** draw it, type it, or upload a photo of it. The white paper in an uploaded photo becomes see-through.
- **Mark up:** highlight, strike out and underline. They snap to the lines of text you drag over. There is also freehand drawing, a see-through marker, and sticky notes, which are saved as real PDF notes.
- **Shapes:** rectangle, ellipse, line and arrow. You can set the colour, fill, line width and how see-through they are.
- **Links:** to a web address, an email address, a phone number, or a page number. They are saved as real links.
- **Forms:** you can fill in a PDF's existing form boxes (text, tick boxes, choices, lists), and add new text fields and tick boxes.
- **Pages:** each page has buttons to turn it, move it up or down, add a blank page after it, or delete it. All of these can be undone.
- **Attachments:** you can see and download files attached inside a PDF, and attach new ones.
- **Smaller extras:** "On every page" copies a change to all pages. Ctrl+C / Ctrl+V copy and paste a change, arrow keys move it, and Ctrl + mouse wheel zooms.
- The tools now sit in a rail on the left; on phones it becomes a scrolling row.

## What was broken (fixed)
- **Changed text was saved as a picture**, even in Arial, Times or Courier-style fonts. That made it blurry and the files bigger. Those fonts are now saved as sharp, real text. I checked in the saved file that "Priya Sharma" now uses the PDF's own Times-Bold font.
- **Changed text was covered too widely:** spaces at the end of a line made the cover box wider than the words.
- **Dragging could break** if the page finished redrawing in the middle of the drag.
- **The tests were unreliable:** they sometimes started before the local test server was ready. This caused a failure in my first run of your existing tests.

## How I tested it
I drove the real editor in headless Chrome and checked the saved files with separate tools (qpdf, pdftotext, pdftoppm and pypdf):
- `tests/e2e.mjs` is your existing suite, slightly adjusted. It still passes in full.
- `tests/e2e-features.mjs` is new. It covers every new tool, filling a form, the page tools, attachments, "erase for real" alongside the new objects, protected files, restoring work after a reload, and a phone-sized screen.
- `tests/make_more.mjs` now also makes a test form PDF.

In every run, no request left the computer. The only outside connections were headless Chrome's own Google sign-in and update attempts, which the network blocked; the editor itself made none. I also looked at the rendered pages to check them by eye.

`npm test` runs both suites. The README explains how to make the test files.

## What I did not do
- **Other fonts as real text:** text in your own font files, or in Hindi, Arabic and other scripts, is still saved as a sharp picture. Putting those fonts into the PDF needs a font library that isn't available offline here.
- **Existing content:** you can't move or delete pictures already in a PDF (Cover area hides them), and you can't edit existing links or notes.
- **Some Sejda extras:** stamps, signing with the camera, adding new radio buttons or drop-down fields, tab order, inserting pages from another PDF, and dragging pages to reorder them (it's done with buttons). Sejda's online form publishing is left out on purpose, because it would send data out.
- **Older limits:** sideways text still can't be edited, and Find still misses words split across two lines.
- **Deleted pages:** if a deleted page had form fields, they stay in the file's list of fields, but its contents are removed.
- **Other browsers:** I only tested in Chrome, including a phone-sized emulation. I didn't test Firefox, Safari or a real phone.
