0How to read this page

A program is a list of instructions. Python runs them from top to bottom, one line at a time.

On this page, every dark box is Python code. The green box right under it is the output: what Python prints on the screen when you run that code. The print() instruction is how a program shows something.

print("Hello!")
print(3 + 4)
print("Total:", 3 + 4)
Hello!
7
Total: 7
  • Text goes inside quotes: "Hello!". Python prints the text without the quotes.
  • Without quotes, Python works the value out first: 3 + 4 becomes 7.
  • When you give print several things separated by commas, it prints them on one line with a space between them.

Anything after a # is a comment: a note for humans. Python ignores it.

# This line is a note. Python skips it.
print("Comments are not printed")  # a note at the end of a line
Comments are not printed
Red boxes are errors

Sometimes we show code that is wrong on purpose. Then Python stops and prints an error message. The red box shows the most important part: the last line of that message (Python also prints a few lines above it that say where the problem is).

print(Hello)
NameError: name 'Hello' is not defined

Python thought Hello (without quotes) was the name of a variable, and there is no variable with that name. Reading the last line of an error is a great habit: it usually tells you what went wrong.

Predict first

Yellow "?" boxes hide the output. Guess what Python will print before you press "Show the answer". Guessing and then checking is the fastest way to learn.

1Variables: names that point to values

A variable is a name that points to a value. Think of a name tag on a string, tied to a box.

age = 30
name = "Asha"
print(name, "is", age)
Asha is 30
= is not "equals" from maths

In Python, = means "make the name on the left point to the value on the right". Python first works out the right side, then attaches the name. To compare two values, Python uses == (two equals signs) — see Operators.

A name can be moved to a new value

Using = again with the same name moves the tag to a new value. The line score = score + 5 looks impossible in maths, but in Python it simply means: take the value score points to now, add 5, and make score point to the result.

score = 10
print(score)
score = 15
print(score)
score = score + 5
print(score)
10
15
20

Two names, one value

What happens when you write b = a? Step through it and watch the arrows.

a = 5
b = a
a = 7
print(a, b)

If you want a separate list, make a copy with .copy(). Now there are two lists, and changing one does not change the other:

x = [1, 2]
y = x.copy()
y.append(3)
print(x)
print(y)
[1, 2]
[1, 2, 3]
Remember
  • name = value points a name at a value.
  • b = a makes b point to the same value as a. No copy is made.
  • Moving a name with = never affects other names.
  • But if two names point to the same changeable value (like a list) and you change that value, both names "see" the change.

Rules for names

  • Use letters, digits and the underscore _. A name cannot start with a digit: score2 is fine, 2score is not.
  • No spaces. Python style is lower case with underscores: first_name, total_price.
  • Upper and lower case are different: first_name and First_name are two different names.
  • You cannot use Python's own words such as if, for, class or True as names.
  • Choose names that say what the value means: price is better than p.
first_name = "Ravi"
First_name = "Meera"
print(first_name)
print(First_name)
Ravi
Meera

Several names at once, and swapping

x, y = 1, 2
print(x, y)
x, y = y, x
print(x, y)
1 2
2 1

On the second line Python first works out the right side (y, x gives 2 and 1), and only then points x at 2 and y at 1. That is why the swap works.

The value has a type, not the name

Every value has a type (number, text, ...). type() tells you which. A name can point to any type, and can later point to a value of a different type.

thing = 42
print(type(thing))
thing = "forty-two"
print(type(thing))
<class 'int'>
<class 'str'>

Predict the output

a = 1
b = a
a = a + 1
print(a, b)
2 1

b = a points b at the value 1. Then a = a + 1 makes a new value 2 and moves only a to it. b still points to 1.

Predict the output

colors = ["red"]
more = colors
more.append("blue")
print(colors)
['red', 'blue']

colors and more point to the same list, and append changes that list. (When Python prints a list, it shows text items inside quotes.)

float — numbers with a decimal point

Dividing with / always gives a float, even when the answer is a whole number.

Why 0.30000000000000004?

The computer stores floats in binary (base 2), and many decimals such as 0.1 cannot be stored exactly in binary — just like 1/3 cannot be written exactly in decimal (0.3333...). The tiny error is normal and happens in almost every programming language. Use round() when you show results to people.

When converting fails

int() only accepts text that looks like a whole number. Text with a decimal point, or a word, gives an error:

print(int("hello"))
ValueError: invalid literal for int() with base 10: 'hello'

To turn the text "3.5" into a whole number, go through float first: int(float("3.5")) gives 3. Adding text and a number also fails — convert the number with str() first:

Where you will need this: input()

input() lets the user type something while the program runs. It always gives you a str, even if the user types a number. So to do maths with it, convert it: age = int(input("How old are you? ")).

Strings cannot be changed

Once a string exists, you cannot change its characters. Strings are immutable (unchangeable).

word = "Python"

Two tools first: for and if in 2 minutes

To work with collections you need two small tools.

for repeats some lines once for each item. The lines to repeat are indented (moved right, normally by 4 spaces). The line ends with a colon :.

for number in [1, 2, 3]:
    print(number * 10)
print("done")
10
20
30
done

Each time round, the name number points to the next item. print("done") is not indented, so it runs once, after the loop. range(n) gives the numbers 0 up to (not including) n, which is handy for repeating something n times:

for i in range(3):
    print("Round", i)
Round 0
Round 1
Round 2

if decides: it runs the indented lines only when the condition is True. else runs when it is False. elif ("else if") adds more choices.

temperature = 31
if temperature > 30:
    print("Hot day")
elif temperature > 20:
    print("Nice day")
else:
    print("Cool day")

6Classes and objects (OOP), the easy way

Object-oriented programming (OOP) lets you make your own types. A Dog type, a BankAccount type... each one bundles some data together with the actions that work on that data.

First, a function in 1 minute

Classes are built from functions, so here is the minimum you need. def creates a function: a named recipe of steps. The values in brackets are its parameters (inputs). return sends a result back to whoever called it.

def greet(name):
    return "Hello, " + name + "!"

message = greet("Asha")
print(message)
print(greet("Ravi"))
Hello, Asha!
Hello, Ravi!

The function body is indented. Defining a function does not run it; greet("Asha") runs it, with name pointing to "Asha". A function without return gives back None — that is why numbers.sort() gave None earlier:

def say_hi():
    print("Hi!")

result = say_hi()
print(result)
Hi!
None

Class and object: blueprint and thing

A class is a blueprint: it describes what every dog has (a name, an age) and can do (bark). An object (also called an instance) is one real thing built from that blueprint: Rex, Bella. One class, as many objects as you like.

You have already used objects: "hello" is an object of the class str, and [1, 2] is an object of the class list. That is why type(42) printed <class 'int'>.

__init__ and self

class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def bark(self):
        print(self.name, "says woof!")

rex = Dog("Rex", 3)
bella = Dog("Bella", 5)
print(rex.name)
print(bella.age)
rex.bark()
bella.bark()
Rex
5
Rex says woof!
Bella says woof!
  • class Dog: starts the blueprint. Class names use CapitalLetters by convention.
  • Functions written inside a class are called methods.
  • __init__ (two underscores on each side; say "dunder init") is a special method that Python runs automatically every time a new object is made. Its job is to set up the new object's starting data.
  • self is the object itself — the particular dog being set up or used. Every method gets it as its first parameter.
  • self.name = name stores the value on the object. Values stored on an object are called attributes. Read them with a dot: rex.name.

The same happens with every method call: rex.bark() means "run bark from the class Dog, with self = rex". These two lines do exactly the same thing:

class Dog:
    def __init__(self, name):
        self.name = name

    def bark(self):
        print(self.name, "says woof!")

rex = Dog("Rex")
rex.bark()
Dog.bark(rex)
Rex says woof!
Rex says woof!
Common mistake: forgetting self

If you write name = name instead of self.name = name inside __init__, the value is only kept while __init__ runs and is then lost. To store something on the object, always write self. in front.

Attributes and methods

Attributes are the object's data (what it has). Methods are its actions (what it does). Methods can read and change the object's attributes through self, and they can return values.

class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance += amount

    def withdraw(self, amount):
        if amount > self.balance:
            print("Not enough money!")
        else:
            self.balance -= amount

    def summary(self):
        return f"{self.owner} has {self.balance}"

account = BankAccount("Asha", 100)
account.deposit(50)
print(account.balance)
account.withdraw(500)
account.withdraw(30)
print(account.summary())
empty = BankAccount("Ravi")
print(empty.summary())
150
Not enough money!
Asha has 120
Ravi has 0

balance=0 is a default value: if you leave it out, as with Ravi's account, it is 0.

Each object has its own attributes. Changing one object does not change another:

        self.count += 1

Inheritance and super()

Inheritance lets a new class start from an existing one. The new class (the child) gets all attributes and methods of the existing class (the parent), and can add new ones or replace some. Write the parent in brackets: class Cat(Animal):. Read it as "a Cat is an Animal".

class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        print(self.name, "makes a sound")

    def sleep(self):
        print(self.name, "is sleeping")

class Cat(Animal):
    def speak(self):
        print(self.name, "says meow")

class Cow(Animal):
    pass

tom = Cat("Tom")
daisy = Cow("Daisy")
tom.speak()
tom.sleep()
daisy.speak()
print(isinstance(tom, Cat))
print(isinstance(tom, Animal))
print(isinstance(daisy, Cat))
Tom says meow
Tom is sleeping
Daisy makes a sound
True
True
False
  • Cat has no __init__ or sleep of its own, so it uses the ones from Animal.
  • Cat writes its own speak. This overrides (replaces) the parent's version for cats.
  • pass means "nothing here". Cow is an Animal with nothing added.
  • isinstance(obj, SomeClass) asks "is this object a SomeClass?" — a Cat is also an Animal.

super(): use the parent's version too

Often the child wants to add to the parent's method instead of replacing it completely. super() gives you access to the parent class. The most common case is __init__: let the parent set up what it knows about, then add the child's own attributes.

class Animal:
    def __init__(self, name):
        self.name = name

class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)
        self.breed = breed

rex = Dog("Rex", "Labrador")
print(rex.name)
print(rex.breed)
Rex
Labrador

super().__init__(name) runs Animal's __init__ on this same object, which sets self.name. Then Dog adds self.breed. Notice that you do not pass self to super().__init__; Python does it.

If the child has its own __init__ and forgets to call super().__init__, the parent's set-up never runs:

class Animal:
    def __init__(self, name):
        self.name = name

class Dog(Animal):
    def __init__(self, name, breed):
        self.breed = breed

rex = Dog("Rex", "Labrador")
print(rex.name)
AttributeError: 'Dog' object has no attribute 'name'

super() works in any method, not only __init__:

class Animal:
    def __init__(self, name):
        self.name = name

    def describe(self):
        return "I am " + self.name

class Dog(Animal):
    def describe(self):
        basic = super().describe()
        return basic + " and I am a dog"

rex = Dog("Rex")
print(rex.describe())
I am Rex and I am a dog

__str__: what print shows

By default, printing your own object shows something not very helpful: the class name and a memory address (the hexadecimal number at the end will be different every time you run it).

Add a __str__ method that returns a string. Python uses it whenever the object is printed or turned into text with str() or in an f-string.

class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

    def __str__(self):
        return f"{self.title} by {self.author}"

        print(self.title)

Note that "Dune" is printed first by the print inside __str__, and then the program stops with the error.

How Python finds an attribute or method

When you write rex.something, Python searches in this order and uses the first match:

  1. the object itself (its instance attributes),
  2. its class,
  3. the parent class (and the parent's parent, and so on).

If it is found nowhere, you get an AttributeError. This one rule explains class attributes, the "assigning through an object" trap, inheritance and overriding.

    def __init__(self, name, salary, team):
        super().__init__(name, salary)
        self.team = team

    def yearly_pay(self):
        return super().yearly_pay() + 5000

    def __str__(self):
        return super().__str__() + f", manages {len(self.team)} people"

asha = Employee("Asha", 3000)
ravi = Manager("Ravi", 4000, ["Asha", "Leo"])
print(asha)
print(ravi)
print(asha.yearly_pay())
print(ravi.yearly_pay())
Asha (Acme)

36000

Predict the output

class Shape:
    def __init__(self, name):
        self.name = name

    def area(self):
        return 0

    def __str__(self):
        return f"{self.name} with area {self.area()}"

class Square(Shape):
    def __init__(self, side):
        super().__init__("square")
        self.side = side

    def area(self):
        return self.side * self.side

print(Shape("blob"))
print(Square(3))
blob with area 0
square with area 9

__str__ is written only in Shape, but inside it self.area() is looked up on the actual object. For a Square, Python finds Square's own area first, so it gives 3 × 3 = 9.
