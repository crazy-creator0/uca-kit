## Small build
For a small build only, as `new-project` defines it. A substantial new UI gets Steps 1 to 8.

1. **Domain:** who uses it, where and when; the real objects and their states; the users' own words for their jobs, used on screen; believable sample data, never "Item 1" or lorem ipsum. Read any reference shared.
2. **Taste:** follow the user's reference or feel; with neither, decide from the domain and say so. Ask one question only if the look is the point.
3. **Brief, in the plan block:** first your default look in one line (what you would build unguided), then change three parts of it with things from the domain. Direction: list them (`node scripts/uca-read.cjs design-taste-discovery/directions --list`), pick by one concrete fact about this business (invent one if fictional), not the one nearest your default without reason; read only that one (`--section "<name>"`), change two attributes using domain words, and add one signature element from the domain, never the direction's own example; type: named typefaces, not the framework default, and a size scale; color: hex for background, text, one accent and status colors; one spacing step and one corner radius; the main action leads.
4. **Avoid the trained look:** numbered labels ("01 / About"), a status or log card beside the hero, a row of three stats, a faint grid background, three feature cards, stock lines ("software that holds up"); also no hero with a headline and two buttons, purple gradients or glows, cards inside cards, decoration without a task.
5. **Review, pass or fail with evidence:** the code matches the brief; `node scripts/uca-design-check.cjs <ui files>` when installed, each finding fixed or given a product reason; phone width, keyboard, contrast, empty and error states. Evidence is text first; one look at the main screen only if you can read images, else "read, not looked". Never claim a look you did not take.
