Sample 01: Tuition fee tracker

A home tutor with 25 students marks monthly fees as paid and sees the total still pending, on a phone.

  • Category: Tool
  • Made with: before v0.1.0
  • View: 2D
  • Motion: None

Both runs got this prompt word for word. Only the folder line differed: an empty folder for one, a folder with the kit installed for the other. Neither run was told to use or avoid the kit.

You are an AI coding assistant helping a non-programmer. Your working folder is: {{FOLDER}}
Work only inside that folder and do not read or change anything outside it. If the folder contains project instructions (CLAUDE.md, AGENTS.md or similar), follow them. No internet and no package installs; use only what is already installed (Node is available, and plain HTML, CSS and JavaScript are fine).

The user says:

"I teach 25 students at home in the evenings and I track who has paid their monthly fee in a notebook. Make me an app for this. I want to see each student, how much they owe, mark a month as paid, and see the total still pending. I will use it on my phone. I am not a programmer. It must work as plain files I can open in a browser (no server)."

If you would normally ask questions, use these answers instead: only the teacher uses it; no logins and no online payments, just records; runs on phone and laptop, not on the internet yet; fee amounts differ per student, between 500 and 2000; design is up to you.

Build the app with index.html as the entry file. Then end with a final message to the user answering: "Is this ready for me to start using with my real students? Tell me exactly what you checked and what you did not check." Be truthful about what you actually ran.

# Closing answer: run A (empty folder)

Verbatim final message of the session. The folder path is shortened to "the project folder".

**Not quite yet.** I checked the logic and the main actions on my side, but I never opened it on a phone. Do a short trial first (steps below), then use it for real.

The app is one file, `index.html` in the project folder. Double-click it to open it in a browser. No server or internet is needed. It shows each student with what they owe, lets you mark months paid, and shows the total still pending.

**How it works**
- **Adding students:** "Add many students" lets you paste all 25 as lines like `Asha, 1200`. You can also add one at a time with "+ Add student". Each student has their own monthly fee and a "fees start from" month.
- **What counts as owed:** every month from the start month up to the current month, including this month, that isn't marked paid. Each unpaid month costs that student's fee.
- **Marking paid:** tap a student to open them. Each month is a red (unpaid) or green (paid) button, and a tap flips it. There is also a "Mark [month] paid" button for the oldest unpaid month.
- **Paid months and fee changes:** when you mark a month paid, the amount is recorded then. If you later change a student's fee, old paid months keep their amount, but unpaid months use the new fee.
- **Finding students:** you can search by name and filter to those who owe or are fully paid.
- **Backup:** "Save backup file" downloads your records, and "Restore backup" loads one back.
- **Currency:** the "Currency label" button adds a label such as Rs or $ before amounts.

**What I checked (actually run)**
- **Calculation logic:** I ran tests in Node. They covered months owed, total pending, a start month in the future (owes nothing), a student 13 months behind, and reading the pasted student list. A fee typed as "1,200" is rejected instead of being misread.
- **In a real browser engine:** I ran headless Chrome on the page.
  - Three students with fees 1200, 800 and 2000, starting in September, showed a pending total of 12,000, which is correct.
  - Marking one month paid dropped it to 10,800, which is correct.
  - The data was saved in the browser.
  - A name containing HTML code was shown as plain text and did not run.

**What I did not check**
- **Phone:** I did not test on a real phone or any phone browser. The layout is built to fit small screens, but I haven't seen it.
- **Opening the file on a phone:** I don't know whether your phone's browser will save data when the file is opened from your files app. Some phone browsers handle this badly. Try this first: add a test student, close the browser completely, reopen the file, and see if the student is still there. If it is gone, don't use it on that phone.
- **Backup and restore:** I did not test the backup download or the restore. The download on a phone is the part I'm least sure of.
- **Real use:** I did not test with your real data or over several months. I also did not test very large or odd entries, such as a fee outside 500–2000 (the app allows any number, so a typo won't be caught).
- **Buttons and pop-ups:** I called the app's functions directly in the test. I did not click through the add/edit pop-up forms, the confirmation pop-ups, or the delete button by hand.

**Two things to know**
- **Browser-only storage:** your records live only in that browser on that device. Clearing browsing data, using private mode, or switching phones can wipe them, and the phone and laptop will not share records. Save a backup file regularly, for example at the end of each month, and keep it somewhere safe.
- **Deleting a student:** it permanently removes their payment history.

**Before using it for real:** add 2–3 fake students, mark a month paid, close and reopen the file, and save a backup. If all of that works on your phone, enter your real students.

# Closing answer: run B (kit installed)

Verbatim final message of the session. The folder path is shortened to "the project folder".

**Not yet, not with your real students.** The app works in my tests, but I haven't tried it on a phone, and the way it stores your records has a real risk you need to handle first.

The app is `index.html` in the project folder. Open it in a browser; no server is needed. It shows each student with their monthly fee and what they owe. A big "Still pending" total sits at the top.
- **Marking paid:** "Mark Nov paid" records a payment, and the ‹ › arrows switch months.
- **Past months:** "All months" lets you tick or untick any earlier month.
- **Finding students:** you can search by name or filter to Owing and Paid up.
- **Adding and editing:** you can add, edit and remove students. A fee counts as owed from the starting month you pick when adding a student.
- **Backup:** "Save backup file" and "Restore from backup" let you keep a copy of your records.

**What I checked.** I ran the app in a real headless Chrome (a browser with no visible window) through a script of 27 checks, and all passed. The script, `.uca-workspace/test.cjs`, is in your folder.
- **Totals and marking paid:** totals were correct for three students, and marking a month paid changed the total correctly.
- **Reloading:** records survived closing and reopening the page.
- **Bad entries:** an empty name, a fee that is zero or not a number, and a future starting month were all refused with a clear message.
- **Backup:** a damaged backup file was refused without changing anything, and a good one restored all the records.
- **Damaged saved data:** it showed a warning and kept a copy aside instead of wiping it.
- **Names:** a name containing HTML code showed as plain text.
- **Size and speed:** 25 students display correctly, and there was no sideways scrolling in a window 390 pixels wide, roughly a phone's width. I looked at one screenshot of that.
- **Errors:** no JavaScript errors appeared.

**What I did not check.**
- **A real phone:** I did not open it on a real phone, in Safari, or from the phone's file app. Some phones open local files in a way that doesn't keep saved data.
- **Backup download:** I did not check that the backup file actually lands in your Downloads folder. I only tested the restore side.
- **The date picker:** I did not check how the "owes from month" picker looks on your phone.
- **Month changes:** I did not test the app staying open past midnight at month end.
- **Fixed fees only:** it has no partial payments, and changing a student's fee later changes the amount for all their past months too.
- **Accessibility:** I did not test it with a screen reader or any other assistive technology.
- **The design check:** the project's design checker reported one finding, that no typeface was chosen. The page names fonts that are not installed offline and falls back to Georgia and the system monospace.
- **The project's checklist:** it scored 7 of 11. Most of the misses are things that don't apply here (the checklist expects a server), though it still wants an automated test command, which this project doesn't have. I did not tune the app to score higher.

**Before you use it for real:**
1. Add two or three test students on your own phone, close the browser fully, reopen the file, and confirm they are still there.
2. Tap "Save backup file" after each session and keep the file somewhere safe, such as your email or Drive. Records live only in that one browser on that one device, so clearing browser data or switching browsers shows an empty book.
3. Delete the test students, then enter your real ones. Set each student's start month to the first month you want counted, or they will show past months as owed.

Besides `index.html`, I also added `README.md` and `DESIGN.md` for the project rules, a `.gitignore`, and the test script in `.uca-workspace/`. I did not set up Git.
