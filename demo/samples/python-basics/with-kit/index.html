How to read this page

Each example has two parts. The light box is the code you type. The dark box under it is the output: exactly what Python prints when you run that code.

print("Hello, world!")
print(2 + 3)
Hello, world!
5
  • Every example works on its own. Copy one into a new file (in IDLE: File → New File, paste, then Run → Run Module) and you will see the same output.
  • Lines starting with # are comments. Python ignores them. They are notes for you.
  • Errors are shown short. When Python stops with an error, it prints a few lines that say where the error happened. Those lines depend on your file name, so this page replaces them with ... and keeps the first and the last line. The last line is the one to read: it names the error and explains it.
  • The outputs were checked by running every example in Python 3.13.

The >>> shell is slightly different. If you type a value straight into the Python shell (the window with >>>), it shows the value without print, and shows text with quotes: 'hello'. print shows text without quotes: hello. This page uses print everywhere.

1 Variables: names point to values

A variable is a name that points to a value. You create one with =.

In Python, = does not mean "is equal to". It means: work out the value on the right, then tie the name on the left to it.

age = 30
name = "Amina"
print(age)
print(name)
print(name, "is", age)
30
Amina
Amina is 30

print can take several things separated by commas. It prints them on one line with a space between them.

Changing what a name points to

If you use = again with the same name, the tag moves to the new value. The old value is not changed; the name just points somewhere else now.

score = 10
print(score)
score = 25
print(score)
10
25

Because the right side is worked out first, a name can appear on both sides:

count = 5
count = count + 1
print(count)
6

Read it as: take the value count points to (5), add 1, then tie count to the result (6).

Two names, one value

Step through these two small programs. Watch the tags: y = x and b = a do not copy anything. They tie a second tag to the same value.

Try it: step through the code

    Printed so far: 
    x = 5
y = x
x = x + 1
print(x, y)
    6 5
    a = [1, 2]
b = a
b.append(3)
print(a)
print(b)
    [1, 2, 3]
[1, 2, 3]

    [1, 2] is a list (chapter 5), and append adds an item to it. The list itself changed, and both names point to that one list, so both show [1, 2, 3].

    With numbers you never see this effect, because a number cannot be changed. x = x + 1 makes a new value, 6, and moves only the tag x. y still points to 5.

    Rules for names

    • Use letters, digits and the underscore _. No spaces.
    • A name cannot start with a digit: 2nd_place is not allowed, place_2 is fine.
    • Capital letters matter: Age and age are two different names.
    • You cannot use Python's own words such as if, for, class, True or None as names.
    • The usual style is lowercase words joined by underscores: first_name, total_price.
    first_name = "Lee"
Age = 40
age = 41
print(first_name, Age, age)
    Lee 40 41

    Several names at once

    x, y = 1, 2
print(x, y)
x, y = y, x
print(x, y)
    1 2
2 1

    The right side is worked out completely first (2, 1), then the names are tied to the values. That is how the second line swaps x and y.

    Remember

    • = ties a name to a value. The right side is worked out first.
    • Two names can point to the same value. For a list, a change made through one name is seen through the other.

      point = (3, 5)

      Sets

      A set is a bag of unique values. Duplicates are dropped, and there is no order, so there are no indexes.

      Create and read

      colours = {"red", "green", "red", "blue"}
print(len(colours))
print("red" in colours)
print(sorted(colours))
      3
True
['blue', 'green', 'red']

      The second "red" was dropped, so there are 3 items. You cannot ask for colours[0]; you ask "is it in there?" with in, which is very fast for sets, even big ones.

      Do not rely on the order. When you print a set, Python shows the items in whatever order it stores them. It is not the order you wrote and not sorted. With text, it can even change each time you run the program. That is why this page uses sorted() to print sets of text: it gives a sorted list.

      nums = {10, 3, 1, 3}
print(nums)
print(sorted(nums))
      {1, 10, 3}
[1, 3, 10]

      An empty set is written set(). Empty curly brackets {} make an empty dict.

      print(type(set()))
print(type({}))
      <class 'set'>
<class 'dict'>

      Change

      tags = {"python"}
tags.add("beginner")
tags.add("python")
print(len(tags))
tags.discard("missing")
tags.remove("beginner")
print(tags)
      2
{'python'}

      Adding "python" again changes nothing: it is already in the set. discard(x) removes x if it is there and does nothing otherwise. remove(x) gives an error if x is missing.

      Comparing two sets

      alice = {"jazz", "rock", "pop"}
bob = {"rock", "folk", "pop"}
print(sorted(alice & bob))
print(sorted(alice | bob))
print(sorted(alice - bob))

['folk', 'jazz', 'pop', 'rock']
['jazz']

      The same as methods: alice.intersection(bob), alice.union(bob), alice.difference(bob).

      Turning a list into a set is the quickest way to drop duplicates, but the original order is lost. Loop over sorted(...) to get a fixed order.

      visits = ["Ana", "Ben", "Ana", "Cy", "Ben"]

      Dicts

      A dict (dictionary) stores pairs: a key and its value. You look a value up by its key, the way you look up a word in a dictionary to find its meaning.

      Create and read

      phone = {"Ana": "555-0101", "Ben": "555-0199"}
print(phone["Ana"])
print(len(phone))
print(phone.get("Cy"))
print(phone.get("Cy", "unknown"))

unknown

      phone["Cy"] with a missing key is an error. get is the safe way: it gives None, or the default you give it, when the key is missing.

      phone = {"Ana": "555-0101"}

      Change

      Assigning to a key changes its value if the key exists, or adds the pair if it does not.

      stock = {"apples": 10, "pears": 4}
stock["pears"] = 6
stock["plums"] = 12
stock["apples"] -= 3
del stock["pears"]
print(stock)
removed = stock.pop("plums")
print(removed, stock)
      {'apples': 7, 'plums': 12}
12 {'apples': 7}
      settings = {"theme": "light"}
settings.update({"theme": "dark", "size": 14})
print(settings)
      {'theme': 'dark', 'size': 14}

      Keys must be values that cannot change, such as strings, numbers, or tuples of those. A list cannot be a key. Values can be anything.

      Loop

      A plain loop over a dict gives the keys. Use items() to get key and value together. Dicts keep the order in which keys were added.

      prices = {"tea": 2.5, "cake": 3.0}
for item in prices:
    print(item)
for item, price in prices.items():
    print(f"{item}: {price:.2f}")
print(list(prices.keys()))
print(list(prices.values()))

      A classic pattern: counting things. counts.get(ch, 0) gives the count so far, or 0 the first time.

      counts = {}
for ch in "banana":
    counts[ch] = counts.get(ch, 0) + 1
print(counts)
      {'b': 1, 'a': 3, 'n': 2}
      Dict methods at a glance
      MethodWhat it does
      get(key, default)the value, or default (or None) if the key is missing
      keys() / values() / items()all keys / all values / all (key, value) pairs
      pop(key)remove the pair and give back its value
      update(other)add or overwrite pairs from another dict
      copy()make a separate copy
      clear()remove everything

      Which one should I pick?

      Try it: answer up to three questions

      • dict when you look things up by a label: a name to a phone number, a product to its price.
      • set when you only care whether something is in the group, and each thing counts once: the people who visited, the tags on a post.
      • list when order matters and the contents will change: a to-do list, scores as they come in.
      • tuple when a few values belong together and should not change: a date (2025, 3, 14), a point (3, 5).

      When unsure, start with a list. It is the most common choice.

      Remember

      • list [ ] changes, tuple ( ) does not.
      • set { } keeps each item once, in no fixed order. Empty set: set().
      • dict {key: value}: in and loops use the keys.

      6 Classes and objects, the easy way

      So far you have used Python's own types: str, list, dict… A class lets you make your own type. It bundles some data together with the actions that belong to it.

      • A class is the blueprint, like a cookie cutter.
      • An object (also called an instance) is one thing made from it, like one cookie. You can make many objects from one class.
      • Attributes are the object's data: a dog's name and age.
      • Methods are its actions: functions written inside the class, such as bark.

      class, __init__ and self

      class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age

    def bark(self):
        print(f"{self.name} says Woof!")

rex = Dog("Rex", 3)
fido = Dog("Fido", 5)
rex.bark()
fido.bark()
print(rex.age)
print(fido.name)
      Rex says Woof!
Fido says Woof!
3
Fido

      Line by line:

      • class Dog: starts the blueprint. Class names usually start with a capital letter.
      • def defines a function. Inside a class it defines a method.
      • __init__ (two underscores on each side) is the set-up method. Python runs it automatically every time you make a new object with Dog(...). Its job is to give the new object its starting attributes.
      • self is the object itself. In __init__ it is the new object being set up, so self.name = name means "store the name on this object".
      • Dog("Rex", 3) makes a new object and runs __init__ with name="Rex" and age=3. You do not pass self; Python does that for you.
      • rex.age reads an attribute. rex.bark() calls a method.

      Where does self come from?

      When you write rex.bark(), Python turns it into Dog.bark(rex): the object before the dot becomes self. Both lines below do the same thing:

      class Dog:
    def __init__(self, name):
        self.name = name

    def bark(self):
        print(f"{self.name} says Woof!")

rex = Dog("Rex")
rex.bark()
Dog.bark(rex)
      Rex says Woof!
Rex says Woof!

      That is why every method has self as its first parameter, and why self.name inside bark finds the right dog's name.

      Attributes and methods working together

      Methods can read and change the object's attributes. Here if / else picks one of two paths: if there is not enough money, print a message; otherwise take the money out.

      class Account:
    def __init__(self, owner):
        self.owner = owner
        self.balance = 0

    def deposit(self, amount):
        self.balance += amount

    def withdraw(self, amount):
        if amount > self.balance:
            print("Not enough money")
        else:
            self.balance -= amount

acc = Account("Mia")
acc.deposit(50)
acc.withdraw(80)
acc.withdraw(20)
print(acc.owner, acc.balance)
      Not enough money
Mia 30

      Every attribute does not have to come from a parameter: balance always starts at 0.

      Class attributes and instance attributes

      An instance attribute belongs to one object and is set with self.something = ..., usually in __init__. A class attribute is written directly inside the class, and is shared by all objects of that class.

      class Dog:
    species = "Canis familiaris"

    def __init__(self, name):
        self.name = name

      A class attribute is a good place for a counter that all objects share. Change it through the class name:

      class Dog:
    count = 0

    def __init__(self, name):
        self.name = name
        Dog.count += 1

      Trap 1: assigning through an object does not change the class attribute. It creates a new instance attribute on that one object, which hides the class one for that object only.

      class Dog:
    sound = "Woof"

      Trap 2: a list as a class attribute is shared by everyone. Here every student would share one list of grades:

      class Student:
    grades = []  # shared by ALL!

    def __init__(self, name):
        self.name = name

      Ben got Ana's grade, because ana.grades and ben.grades both find the one list on the class. The fix: give each object its own list in __init__.

      class Student:
    def __init__(self, name):
        self.name = name
        self.grades = []  # one each

ben = Student("Ben")
ana.grades.append(90)
print(ana.grades)
print(ben.grades)

      Inheritance

      A class can be built on top of another class. The new class (the child) gets all the methods of the old one (the parent), and can add its own or replace some. Write the parent in brackets: class Dog(Animal):.

      class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        print(f"{self.name} makes a sound")

    def sleep(self):
        print(f"{self.name} is sleeping")

class Dog(Animal):
    def speak(self):
        print(f"{self.name} says Woof!")

class Cat(Animal):
    def speak(self):
        print(f"{self.name} says Meow!")

pets = [Dog("Rex"), Cat("Tom"),
        Animal("Generic")]
for pet in pets:
    pet.speak()
pets[0].sleep()
print(isinstance(pets[0], Animal))
print(isinstance(pets[2], Dog))
      Rex says Woof!
Tom says Meow!
Generic makes a sound
Rex is sleeping
True
False
      • Dog and Cat have no __init__ of their own, so they use Animal's.
      • The same line pet.speak() does different things depending on the object's class.
      • isinstance(x, Animal) asks "is x an Animal, or a child of Animal?". A Dog is an Animal; a plain Animal is not a Dog.

      super(): use the parent's version too

      When the child writes its own __init__, the parent's __init__ no longer runs by itself. Call it with super().__init__(...) so the parent can do its part of the set-up, then add the child's extra attributes.

      class Animal:
    def __init__(self, name):
        self.name = name

class Dog(Animal):
    def __init__(self, name, breed):
        super().__init__(name)
        self.breed = breed

    def describe(self):
        print(f"{self.name} is a {self.breed}")

rex = Dog("Rex", "beagle")
rex.describe()
      Rex is a beagle

      Without the super().__init__(name) line, self.name would never be set and describe would stop with an AttributeError.

      super() works in any method, not only __init__. Here the child adds to what the parent does:

      class Animal:
    def speak(self):
        print("Some generic sound")

class Dog(Animal):
    def speak(self):
        super().speak()
        print("Woof!")

Dog().speak()
      Some generic sound
Woof!

      __str__: how your object looks when printed

      If you print an object from your own class, Python shows something like <__main__.Book object at 0x7f3a2c1b9e50>. The long number is a memory address and is different every time, so it is not shown as an output here. It is not very helpful either.

      Write a __str__ method to choose the text yourself. It must return a string (give it back), not print it. print(), str() and f-strings all use it.

      class Book:
    def __init__(self, title, author):
        self.title = title
        self.author = author

    def __str__(self):
        return f"{self.title} by {self.author}"

b = Book("Dune", "Frank Herbert")
print(b)
print(f"I'm reading {b}")
print(str(b))
      Dune by Frank Herbert
I'm reading Dune by Frank Herbert
Dune by Frank Herbert

      Good to know: when you print a list of books, Python does not use __str__ for the items inside it. It uses a related method, __repr__, which you can learn later. So print([b]) still shows the <... object at 0x...> form.

      Remember

      • A class is the blueprint; Dog(...) makes an object and runs __init__.
      • self is the object the method was called on.
      • self.x = ... makes an attribute for one object; x = ... in the class body makes one shared attribute.
      • class Dog(Animal): inherits; super() reaches the parent's method.
      • __str__ returns the text that print shows.
